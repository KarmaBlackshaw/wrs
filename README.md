# WRS

Water refilling station app. npm-workspaces monorepo:

- `contract/` — `@wrs/contract`, shared zod schemas and types (`.ts` source, no build step)
- `api/` — Fastify + Knex + MySQL
- `ui/` — Vue 3 + Vite

## Requirements

- Node 24 (`nvm use`)
- Docker Desktop (MySQL runs in `api/compose.yaml`)

## Setup

```sh
npm install
npm run setup   # creates api/.env and ui/.env, generates JWT_SECRET
docker compose -f api/compose.yaml up -d --wait db
npm run migrate
npm run seed
npm run dev     # api + ui together
```

| URL | What |
| --- | --- |
| http://localhost:5173 | ui (dev server) |
| http://localhost:3000/api | api (`GET /api/health` → 200) |
| `localhost:3306` | MySQL (`DB_PORT` in `api/.env`) |

`npm run seed` wipes and reloads all data, so run it on a fresh database only. `npm run serve` (api only) starts MySQL and migrates for you.

## Rider app (PWA)

The rider screens install as a PWA from a production build:

```sh
npm run build
npm run preview -w ui   # http://localhost:4173 (already allowed by CORS_ORIGIN)
```

Open it in Chrome, log in as `rider1`, then use the browser's install action. The service worker is only generated by the build, not by `npm run dev`.

## Scripts (run from the repo root)

| Script | What it does |
| --- | --- |
| `npm run dev` | api (`serve`) and ui dev server in parallel |
| `npm run serve` | MySQL up, migrate, api in watch mode |
| `npm run migrate` | latest migrations |
| `npm run seed` | run seeds |
| `npm run db:reset` | roll back all migrations, migrate, seed (the running api keeps serving) |
| `npm run type-check` | type-check every workspace |
| `npm run lint` | lint every workspace |
| `npm run build` | build the ui |
| `npm run db:scratch -w api -- wrs_scratch_<name> [--seed] [--init-only]` | throwaway database for experiments |
| `npm run db:scratch:drop -w api -- wrs_scratch_<name>` | drop it |

**Docker image caveat:** the api `Dockerfile` and the compose `api` profile (`--profile app`) do not build from the workspace layout yet. Run the api with `npm run serve`; only the `db` service is supported in Docker.
